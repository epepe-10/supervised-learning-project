\section{Hyperparameter tuning}
\label{sec:tuning}

\paragraph{Protocol.} We tuned each model with Optuna and its TPE sampler
(seed 42, so a re-run proposes the same trials). In each trial, Optuna proposes
a set of hyperparameters, we build the complete Pipeline with them, score it
with the same 5-fold stratified cross-validation on the development set, and
return the mean AP over the 5 folds; TPE uses all past trials to choose the
next configuration. The budget is 25 trials for the logistic regression, 20 for
the random forest (the slowest to fit) and 50 for LightGBM, which has the
largest search space. A grid search would not fit this budget: three values for
each of LightGBM's eight hyperparameters already make $3^8 = 6{,}561$
configurations, i.e.\ about 33{,}000 fits. A random search would fit it, but
ignores past scores, whereas TPE spends more trials in the promising regions.
The search spaces (Table~\ref{tab:search-spaces}, appendix) include the class
weighting, from none up to the class ratio (Section~\ref{sec:imbalance}). We
optimize AP because it judges the ranking of the minority class without
depending on a threshold, which is chosen afterwards.

\paragraph{Why the best CV score is optimistic.} The best of 20 to 50 trials is
selected on the same folds that score it, so part of its advantage is luck on
these folds. We therefore do not report it as our final result: the honest
estimate comes from the test set, which played no role in tuning
(Section~\ref{sec:test}). Nested cross-validation would remove this bias
without a test set, but would multiply the cost of tuning by five; with
48{,}790 rows, a held-out test set was the cheaper option.

\paragraph{Final training.} For each model, \code{train.py} (1) computes the
out-of-fold probabilities of the tuned Pipeline on the same 5 folds,
(2) chooses the threshold that maximizes F1 on them and freezes it, (3) refits
the Pipeline on the whole development set, and (4) saves it with its
threshold.

\begin{itemize}
  \item \textbf{Edges of the ranges.} Only \code{max\_features} $= 0.60$ for
  the random forest landed on a bound; we did not extend it, since the forest
  stays well behind LightGBM.
  \item \textbf{Class weighting.} No weight for the logistic regression,
  \code{"balanced"} for the forest, 1.80 for LightGBM: since the threshold is
  tuned afterwards, the weight is one more hyperparameter, kept when it helps
  AP.
  \item \textbf{A flat optimum for LightGBM.} Its best trial is trial 2: the 47
  following trials did not beat it (Figure~\ref{fig:lgbm-history}, appendix).
  Below a learning rate of 0.02, even 1{,}000 trees do not finish learning
  (mean AP 0.811 over 2 trials); above 0.1, each tree corrects too much at once
  (0.826 over 21 trials); between the two, the 27 trials average 0.829 and the
  ten best lie within 0.002 AP, about the variation across folds. The selected
  $\eta = 0.048$ with 350 trees is one good point of a plateau, and more trials
  would not change the model much.
\end{itemize}

\subsection{What the penalty does to the logistic regression}
\label{sec:regularization}

The regularization path (train and validation AP for $C$ from $10^{-4}$ to
100, \code{l1\_ratio} = 0.77; Figure~\ref{fig:regularization-path}, appendix)
shows three things. \textbf{Sparsity:} the L1 part of the tuned penalty sets 9
of the 91 coefficients exactly to zero (seven rare \code{native-country}
categories, \code{workclass} = Never-worked, \code{relationship} =
Not-in-family), where Ridge would only shrink them. \textbf{Strong penalty =
underfitting:} at $C = 10^{-4}$ every coefficient is zero and the model
predicts the base rate (AP 0.24). \textbf{Weak penalty does not overfit
here:} above $C \approx 0.1$ the validation AP is flat (0.782 to 0.784) and
the train--validation gap stays below 0.004 even at $C = 100$, since 39{,}000
rows cannot be memorized by 91 coefficients. The tuned $C = 1.89$ lies in this
flat region, which is why tuning did not improve the model; $C = 0.1$ would
give a shorter model (39 coefficients) for only 0.002 AP less.
